# 半间屋 · Half a Room

一间正在消失的宿舍，一半是拍下来的，一半是想起来的。

3DGS 扫描能到的地方是"拍的"，扫不到的角落留下来是黑的。那些黑洞对应着主人记不清的东西——把洞当成提问，问一句"这里原来放的是什么"，用 Lux3D 生成，再摆回原位。

**在线 Demo**：https://modelscope.cn/studios/sinria/half-a-room

## 它是什么

- 一间真实的本科宿舍（河南大学，两人间，2026 年 11 月清空），用手机绕行拍摄 8 分 20 秒，Reality 重建为 3DGS 场景
- 扫描缺失的位置（柜子背后、床底、门口）不是被补掉的，而是被保留下来
- 图鉴里四件东西——绿台灯、一摞书、纸箱、旧行李箱——每件对应一句"记得的样子"，用 Lux3D 文生 3D 生成米制 glTF
- 生成物按标定尺度摆回原位，与 3DGS **在同一个渲染器、同一帧**里渲染
- 可以第一人称走进去（WASD + 鼠标），也可以点图鉴让镜头飞过去

## 技术栈

| 环节 | 用什么 | 说明 |
| --- | --- | --- |
| 重建 | Aholo Reality | 手机视频 → 3DGS，SPZ 输出 |
| 生成 | Aholo Lux3D（G1-Turbo） | 一句描述 → 米制 glTF，带 PBR |
| 渲染 | Aholo Viewer（MIT） | 纯前端 WebGL，3DGS 与网格同帧 |
| 部署 | ModelScope 创空间 | 静态托管，无需后端 |

**资产为什么离线生成**：文生 3D 需要 API Key，Key 进浏览器等于公开。所以四件资产在本地批量生成、下载 glb、随构建产物发布，线上只做读取与渲染。

## 目录

```
app/            场景页面（Vite + TypeScript）
  src/config.ts     场景地址、默认机位、地面高度、米/单位换算
  src/orbit.ts      轨道相机（支持任意 up 轴，带地面钳制）
  src/walk.ts       第一人称行走（WASD + 指针锁定，失败退回拖动）
  src/mesh-loader.ts  GLB 载入与摆放
  src/catalog.ts    图鉴数据与面板
tools/          一次性脚本：点云分析、机位复现、截图、资产下载
```

## 本地运行

```bash
cd app
npm install
npm run dev
```

场景文件与生成资产不进仓库（体积太大）。把 `scene.spz` 放到 `app/public/scenes/`，glb 放到 `app/public/assets/`，`catalog.json` 里写好摆放即可。

URL 参数：

- `?scene=./scenes/xxx.spz` 换场景
- `?cam=ex,ey,ez,tx,ty,tz` 复现机位（页面里按 `P` 复制当前机位）
- `?mode=walk` 直接进入行走
- `?chrome=0` 隐藏界面，只出渲染图

## 踩过的坑（写下来省得再踩）

1. **扫描件的竖直轴是 +Y**。按 -Y 处理会让整个房间颠倒——天花板当地板，物件全贴在天花板上，从颠倒的视角看却像放在地上。
2. **扫描件没有真实尺度**（`has_metric_scale=false`）。用房间里的标准件当尺子：键盘 0.85 单位 = 44cm、桌高 1.44 单位 = 75cm，两路都指向 0.52 m/单位。
3. **网格不给环境光就是全黑**。扫描件的明暗烘在颜色里，网格要真实光照。
4. **`GLTFLoader.loadGLTF` 的字符串参数是 JSON 内容不是 URL**。GLB 要自己 fetch 成 ArrayBuffer，贴图相对路径按 GLB 所在目录解析。
5. **不要用 Git LFS 托管场景**。静态托管不做 smudge，会把指针文件当资产发出去，页面直接黑屏。
6. **改了 `catalog.json` 要防缓存**，否则浏览器还读旧的摆放数据。

## 数据

- 房间 3.5 × 5.3 × 2.77 m（6.8 × 10.1 × 5.32 场景单位）
- 四版重建：注册帧 321 / 382 / 723 / 515，定版 v3（65.1%，4,650,201 高斯，88.8 MB）
- 加参数是负收益：15M 高斯档只收敛到 1,505,520 个更糙的高斯，画面反而更差
